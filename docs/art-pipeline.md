# Пайплайн моделей: Blender → Unity

Проверенная связка: **Blender 5.1.2 + Unity 6000.3.24f1**. Эталон — `Assets/_Rubezh/Art/Source~/Etalon.blend`
(`MM-04`), сцена проверки — `Assets/_Rubezh/Scenes/Sandbox/Sandbox_Maria.unity`.

## 1. Единицы и оси

- Метры: Scene → Units → Metric, Unit Scale 1,0. 1 единица Unity = 1 м.
- Модель **лицом к −Y** Blender (к камере вида Front, Numpad 1). Тогда в Unity перёд смотрит в **+Z**.
- Правая сторона остаётся правой, зеркала нет: FBX сам переводит правую систему координат Blender
  в левую Unity. Соответствие осей: Blender **−Y → Unity +Z**, **Z → Y**, **−X → +X**.
  Значит, правая сторона модели (если смотреть из-за неё, как стрелок) в Blender лежит на −X.
- Масштаб и поворот объектов в Blender — применены (Ctrl+A → All Transforms), кроме пустышек и
  подвижных частей, у которых поворот осмысленный (`MagWell`, `Grip_Primary`).

## 2. Настройки экспорта FBX

File → Export → FBX (.fbx), или скрипт `tools/blender/rubezh_fbx.py`:

| Настройка | Значение |
|---|---|
| Limit to | Selected Objects (или коллекция модели) |
| Object Types | Empty, Mesh |
| **Apply Scalings** | **FBX All** |
| **Forward** | **−Z Forward** |
| **Up** | **Y Up** |
| **Apply Unit** | включено |
| **Apply Transform** | **включено** (экспериментальная опция Blender) |
| Geometry → Apply Modifiers | включено |
| Geometry → Smoothing | Face |
| Armature → Add Leaf Bones | выключено |
| Bake Animation | выключено |
| Path Mode | Auto, Embed Textures выключено |

С настройками по умолчанию модель приезжает в Unity повёрнутой на −90° по X (270°) и в 100 раз
крупнее — это и проверяет эталон.

Скрипт делает то же одной строкой и заодно считает треугольники:

```python
exec(open(r"<репозиторий>/tools/blender/rubezh_fbx.py", encoding="utf-8").read())
export_collection("Pistol", "//../Weapon/Pistol.fbx")   # → число треугольников
```

## 3. Иерархия, имена, пивоты

- Корень модели — пустышка с именем модели (`Pistol`, `Magazine`, `TargetMechanism`) в начале
  координат. Все детали и пустышки — её дети. Одна модель — одна коллекция Blender.
- Имена из иерархий §5.2 ТЗ не меняем без согласования с Никитой: код и интерактив ищут части по
  именам (`Slide`, `Muzzle`, `MagWell`, `Round_01`…).
- **Подвижные части — отдельными объектами.** Начало координат детали там, откуда она движется;
  ось движения совпадает с локальной осью. Затвор `Slide` — начало в положении впереди, ход назад
  по локальной +Y Blender (в Unity — по локальной −Z). Спуск `Trigger`, предохранитель
  `SafetyLever` — начало на оси поворота, поворот вокруг локальной X.
- **Пустышки** (Empty) — точки для кода: `Muzzle` без поворота (её +Z в Unity — направление
  ствола), `EjectionPort`, `MagWell`, `Grip_Primary`, `Grip_Secondary`, `HeadAnchor`, места окружения.

**Вложенность глубже одного уровня** (`MM-10`). С Apply Transform экспортёр FBX переводит оси
только у прямых детей корня: «дети детей» приезжают в Unity с повёрнутыми и сдвинутыми
трансформами. Поэтому в `.blend` иерархия настоящая, а перед экспортом детали переподвешиваются
к корню с теми же мировыми положениями (`flatten_for_fbx()` в `tools/blender/target_mechanism.py`).
Иерархию из `§5.2` собирает префаб в Unity (`Prefabs/Art/TargetMechanism`): он ссылается на меши FBX,
так что повторный экспорт обновляет геометрию без пересборки.

## 5. Материалы, UV, текстуры

- Прозрачности нет нигде: стёкла очков и коридора — непрозрачный материал с бликом на текстуре.
- Блок-модели — простые цветные материалы `MM_Blockout_*` / `YG_Blockout_*`; в Unity они
  заменяются материалами проекта.
- Финал: один атлас оружия и снаряжения 1024×1024 (`MM-13`), один атлас окружения 2048×2048
  (`YG-12`), материалы Simple Lit или Unlit.
- Атласы — палитры: сетка 4 × 4 ячеек, в каждой цвет `docs/palette.md` с фактурой
  (`tools/art/palette_atlas.py`, лежат в `Art/Atlas/`). Модель строится с материалами-цветами как
  раньше, затем `tools/blender/atlas.py` раскладывает каждую грань в ячейку своего цвета (проекция
  с сохранением пропорций, поле 4 % от края) и оставляет один материал: `ENV_Atlas` у окружения,
  `MM_Atlas` у оружия и снаряжения. Оружие переводит на атлас `tools/blender/weapon_atlas.py` прямо
  из `.blend`, FBX пишутся по тем же путям. Свои материалы остаются только у мишенного листа
  (печать `MM-12`), вспышки (`MM-17`) и табличек (`YG-11`).
- Если префаб распакован из FBX (мишенный механизм), после смены материала в импорте ссылка в
  префабе становится пустой — материал ставится в префабе напрямую.
- У всей статики окружения второй UV-канал для lightmap: свой из Blender (UV Map 2) или
  Generate Lightmap UVs в импорте Unity.

## 6. Где лежат файлы

| Что | Путь |
|---|---|
| Исходники `.blend` | `Assets/_Rubezh/Art/Source~/` — папку с `~` Unity не импортирует |
| FBX оружия и снаряжения | `Assets/_Rubezh/Art/Weapon/`, `Art/Equipment/`, `Art/Target/` |
| FBX окружения | `Assets/_Rubezh/Art/Environment/` |
| Визуальные префабы | `Assets/_Rubezh/Prefabs/Art/` — из них Никита делает Prefab Variant с XRI |

Почему `Source~`, а не `Source`: Unity пытается импортировать `.blend` сам, запуская Blender, и
без установленного Blender пишет в консоль «Blender could not be found». В Unity идут только FBX.
В Blender отключить резервные копии: Preferences → Save & Load → Save Versions = 0 (`*.blend1`
и так в `.gitignore`).

`.blend` коммитим на вехах, а не каждое сохранение: Git LFS хранит каждую версию целиком, квота
10 ГиБ на организацию.

## 7. Импорт в Unity

Model Importer для каждого FBX:

| Вкладка | Настройка | Значение |
|---|---|---|
| Model | Scale Factor | 1 |
| Model | Convert Units | включено |
| Model | Bake Axis Conversion | выключено |
| Model | Import Cameras / Lights | выключено |
| Model | Generate Lightmap UVs | только для статики окружения без своего UV2 |
| Rig | Animation Type | None |
| Animation | Import Animation | выключено |
| Materials | Material Creation Mode | Import via MaterialDescription, затем Remap на материалы проекта |

Проверка после импорта: у корня и деталей rotation (0,0,0), scale (1,1,1), размер совпадает с
Blender (Mesh Renderer → Bounds), пивоты подвижных частей на месте.

## 8. Эталонный куб (`MM-04`)

`Etalon.blend`: куб 1 × 1 × 1 м с началом координат в центре нижней грани и две дочерние детали:

| Объект | Blender, положение от родителя | Ожидаем в Unity | Зачем |
|---|---|---|---|
| `Etalon_Cube` | (0; 0; 0), размер 1 × 1 × 1 | rotation (0,0,0), scale (1,1,1), размер 1 м | масштаб и поворот |
| `Etalon_FrontKnob` | (0,3; −0,6; 0,8) — из передней грани | (−0,3; 0,8; 0,6) — перед, +Z | перёд модели, пивот ребёнка |
| `Etalon_MarkPlusX` | (0,55; 0; 0,5) | (−0,55; 0,5; 0) | ось X без зеркала |

Результаты проверки — §9.
