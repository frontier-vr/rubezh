# Производительность

Цели на Quest 2: **стабильные 72 Гц**, до **150 тыс. треугольников** и до **150 draw calls** в кадре.
Замер на шлеме — OVR Metrics Tool в пресете Basic (Advanced сам нагружает шлем), собранный APK.
Оверлей:

```bash
adb shell am broadcast -n com.oculus.ovrmonitormetricsservice/.SettingsBroadcastReceiver -a com.oculus.ovrmonitormetricsservice.ENABLE_OVERLAY
```

## Решения

- **Динамическое разрешение OpenXR — включено** (`NG-21`, 16.10). Подробности ниже.
- **Оттенок очков — оставляем, on-tile** (`NG-30`, 22.10), с выключателем в `RulesConfig`. Подробности ниже.

### Динамическое разрешение (`NG-21`)

**Проверено, что есть в нашей связке.** В пакете Unity OpenXR 1.18 (Unity 6000.3, URP 17, Vulkan)
есть своя функция **Automatic Viewport Dynamic Resolution** (`AutomaticDynamicResolutionFeature`,
группа Android, `All Features`). Она живёт в самом пакете OpenXR: сама запрашивает у рантайма
расширение `XR_META_recommended_layer_resolution` (Quest) или `XR_ANDROID_recommended_resolution`
и меняет область вывода каждый кадр по рекомендации рантайма. Пакет Unity OpenXR: Meta для неё не
нужен — его в проект не ставим (тянет AR Foundation и Composition Layers, ТЗ). Раньше, до
Unity 6.3, динамическое разрешение на OpenXR давали только Meta XR SDK (`OVRManager`) или пакет
OpenXR: Meta — обе дороги нам закрыты.

**Решение: включить сейчас**, как советует Meta, а не перед сдачей.
- `Project Settings → XR Plug-in Management → OpenXR → Android → All Features →
  Automatic Viewport Dynamic Resolution` включена; Min Resolution Scalar **0,7**, Max **1,0**.
  Ниже 0,7 текст табличек и табло на 2 м мылится; 0,5 — нижний предел движка.
- На `Main Camera` включён `Allow Dynamic Resolution` (рекомендация Unity для URP).
- Режим совместимости URP не используем — в нём функция не работает.

**Что остаётся проверить на шлеме** (строка замера выше, ждёт APK `NG-01`): что рантайм Quest 2
сообщает поддержку расширения (`AutomaticDynamicResolutionFeature.IsAutomaticDynamicResolutionScalingSupported()`)
и что в OVR Metrics виден масштаб ниже 1,0 под нагрузкой при стрельбе. Если расширения нет,
функция ничего не делает и кадр рендерится в полном разрешении — сборка не ломается. Запасной путь
без расширения — `XRSettings.renderViewportScale` из своего скрипта по времени кадра; его
делаем, только если замер покажет просадку ниже 72 Гц.
- **Свет запечённый** (`NG-17`, 16.10). Подробности ниже.

### Финальная графика и свет (`NG-17`)

- Всё окружение — финальные модели на одном атласе (`YG-10`, `YG-12`), оружие и снаряжение — на атласе
  1024 (`MM-13`). Блок-моделей в сцене не осталось.
- **Свет только запечённый**: `Directional Light` выключен, 10 прямоугольных (Area) источников под
  светильниками, режим Baked, 45 единиц, тёплый белый. Реального света и теней нет — URP: HDR выключен,
  тени главного света выключены (как и было). Настройки — `Scenes/Main_Lighting.lighting`:
  Progressive GPU, только Baked GI, 12 текселей на метр, атлас до 1024, ненаправленные lightmap, AO,
  3 отскока. Получилась одна карта 1024 (`Scenes/Main/Lightmap-0_comp_light.exr`), запекание ~20 с.
- **Подвижное** (пистолет, магазин, СИЗ, гильзы, мишень, руки) освещают **light probes**: сетка
  165 зондов на 0,4 / 1,2 / 2,0 м — зал через метр, коридор через два.
- **Static**: окружение помечено Contribute GI + Batching / Occluder / Occludee / Reflection Probe Static.
  Исключения: кнопка и регулятор пульта (двигаются) и всё, на чём стоит ключ подсветки `VP-21` (контуры
  мест, лоток, метки якорей) — им только Contribute GI: статическое объединение подменяет их меш общим,
  и копия-подсветка нарисовала бы весь объединённый меш.
- Static Batching на Android включён (по умолчанию, проверено), SRP Batcher включён, GPU Instancing не
  используем.
- Бюджет в редакторе: ~21 тыс. треугольников и 46–57 batches — запас до 150 тыс. и 150 draw calls
  большой. 72 Гц на шлеме — строка Quest 2 выше, после APK (`NG-01`).

### Оттенок очков на on-tile постпроцессинге (`NG-30`)

- **Рендерер** `Settings/URP_Renderer`: встроенный Post-processing выключен (Post Process Data пусто),
  добавлен Renderer Feature **On Tile Post Processing (Untethered XR)**. В URP Asset Opaque Texture и
  Depth Texture выключены, HDR выключен — лишних копий кадра нет. Основная камера: Post Processing
  включён (без него фича не работает); камеры мишени, стоп-кадра и повтора — без постпроцессинга.
- **Оттенок** — глобальный Volume `Exercise/GlassesTint`, профиль `Settings/GlassesTint_Profile`:
  Color Adjustments → Color Filter `#DCE5E8` (холодный, от стёкол `#6E7E86` в `docs/palette.md`).
  Вес 1, пока очки надеты (`IWearables.GlassesOn`), 0 — сняты, переход 0,2 с (`GlassesTint`,
  `RulesConfig.glassesTintSeconds`). При весе 0 Volume выключен.
- **Замер в редакторе** (строки 22.10 выше): 1,69 мс без оттенка и 1,63 мс с ним — в пределах шума.
  В редакторе фича работает в запасном режиме (чтение текстуры, не on-tile): XR в Play Mode не
  запущен. On-tile включается только на Android с активным XR, то есть на шлеме.
- **Решение — оставляем**: цветокоррекция из списка on-tile (Color grading) и стоит один проход по
  тайлу. Если строка Quest 2 покажет меньше 72 Гц при стрельбе — снять галку
  `RulesConfig.glassesTintEnabled`, оттенок выключится целиком без пересборки сцены. Render Graph
  Viewer на шлеме и строку OVR Metrics добавить по APK (`NG-01`). Исключение к ТЗ §7.3 п. 4 —
  `docs/decisions.md`, Р-07; Юле для дизайн-документа — объект 5.
