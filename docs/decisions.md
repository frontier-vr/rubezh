# Решения команды

Короткий журнал решений, которые держат работу с репозиторием и проектом.
Новое решение дописывается снизу: дата, что решили, почему, что из этого следует.

## Р-01 · 25.09 · Слияние только merge-коммитом

**Решение.** PR сливаются только merge-коммитом. Squash и rebase в настройках репозитория
выключаются (Settings → General → Pull Requests: оставить только «Allow merge commits»).

**Почему.** В `main` и `dev` должны попадать личные коммиты со своими авторами: по ним
преподаватель видит вклад каждого, а GitHub строит график вклада. Squash склеивает коммиты
в один от имени того, кто нажал кнопку.

**Следствие.** Кнопку «Squash and merge» не нажимаем, даже если она доступна.
Настройку в репозитории переключает администратор (Никита).

## Р-02 · 25.09 · Защита `main` и ветка `dev`

**Решение.**
- Работа идёт в ветках задач: одна задача — одна ветка — один PR. Имя ветки указано в issue
  (`nikita/NG-00-repo-setup`, `vlad/VP-04-exercise-director`, ...).
- PR из ветки задачи идёт в `dev`. В конце спринта `dev` сливается в `main` одним PR,
  и `main` всегда содержит состояние, которое показывали на вехе.
- Защита `main` (правило ветки): запрет прямого push и force-push, запрет удаления,
  слияние только через PR. Обязательное одобрение не включаем: в команде четыре человека,
  и при болезни одного ревьюера PR встанет. Ревью по `CODEOWNERS` держится на договорённости:
  свой PR никто не сливает без отзыва второго владельца пути.
- Для `dev` защиты нет, но правила те же: только через PR, только merge-коммит.

**Почему.** Без защиты правила держатся на договорённости (ТЗ §9.1); минимальная защита
снимает самые дорогие ошибки (force-push и прямой коммит в `main`) и не блокирует работу.

**Следствие.** Правило ветки для `main` включает администратор (Никита) в
Settings → Branches. До этого правило выполняется по договорённости.

## Р-03 · 25.09 · Главную сцену правит один человек

**Решение.** `Assets/_Rubezh/Scenes/Main.unity` правит только Никита. Остальные работают в
своих песочницах `Assets/_Rubezh/Scenes/Sandbox/Sandbox_<Имя>.unity` и отдают префабы.

**Почему.** Конфликт слияния в сцене Unity разбирается плохо даже через UnityYAMLMerge
(`NG-02`); проще его не допускать.
